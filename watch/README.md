# watch/：手錶計分（Wear OS）

Galaxy Watch 上的計分板，可以看比分、加減分、切換全場半場和開新局。資料和網頁計分板是同一份，操作後所有裝置都會同步。Kotlin 加 Compose for Wear OS，不需要手機端的配套 App。

實測手錶是 SM-L330（Android 16）。

## 操作

| 操作 | 結果 |
| --- | --- |
| 點左半邊或右半邊 | 該隊加一球：半場 +1、全場 +2，和網頁相同 |
| 左半邊或右半邊上滑 | 該隊 +1 |
| 左半邊或右半邊下滑 | 該隊 −1，分數不會減到負的 |
| 點上方的「半場／全場」按鈕 | 切換模式，所有裝置一起換 |
| 下鍵連按兩下 | 歸零：目前這場存進紀錄，開新的一場，隊名和模式沿用。3 秒內要按第二下，第一下只會提示 |
| 右滑或按上鍵 | 離開 App |

- **上鍵不能自訂**：它是電源鍵，系統會先攔走，App 收不到。
- **下鍵長按不能用**：系統會開 Samsung Wallet。
- **回饋**：操作成功時手錶震一下；失敗時震動不同，畫面顯示「連線中斷」。

## 網路

比分都存在雲端的 Supabase，手錶要連得到外網。App 不用管走哪一條，系統會自動選：

| 手錶狀態 | 資料怎麼走 |
| --- | --- |
| 連著可用的 Wi-Fi | 直接走 Wi-Fi，不經過手機 |
| 沒有 Wi-Fi | 藍牙經手機上網，手機用 Wi-Fi 或行動數據都可以 |

所以在球場不用開熱點，手機能上網、藍牙連著就好。平板沒有 SIM 卡時才需要熱點。藍牙路線在手機連 Wi-Fi 時實測過，手機用行動數據的情況還沒測。

**斷網時**：手動加分會失敗，不會排隊補送。這點和偵測 App 不同，偵測 App 的進球會存在手機裡，恢復連線後補上。

手錶的 Wi-Fi 只有開發時才必要：電腦用無線 adb 連手錶除錯和安裝 App 要用它，打球時用不到。

## 開發

```bash
# PATH 上的 java 太舊時，先把 JAVA_HOME 指到 Android Studio 內附的 JBR
./gradlew assembleDebug

adb pair <手錶IP>:<配對埠> <配對碼>   # 只有第一次要配對
adb connect <手錶IP>:<連線埠>         # 連線埠常常換，看「無線偵錯」主畫面
adb install -r build/outputs/apk/debug/scoreboard-watch-debug.apk
```

依賴版本停在支援 compileSdk 36 的組合，因為 AGP 9.1.0 只支援到 36，要升級得連 AGP 一起升。

| 檔案 | 內容 |
| --- | --- |
| `src/main/java/.../MainActivity.kt` | 畫面、手勢、按鍵、每 2 秒更新比分 |
| `src/main/java/.../ScoreApi.kt` | 呼叫 Supabase REST API |

## 測試

目前沒有自動測試，都是在手錶上操作，而且會寫入正式資料。歸零會在比賽紀錄留下一場，不要的話到網頁刪除。
