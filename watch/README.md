# watch/：手錶計分（Wear OS）

Galaxy Watch 上的計分板，可以看比分、加減分、切換全場半場和開新局。比分存在手錶上，沒網路也照記；有網路時和網頁計分板同步，場邊的平板另外用藍牙直接收。Kotlin 加 Compose for Wear OS，不需要手機端的配套 App。

實測手錶是 SM-L330（Android 16）。

## 操作

| 操作 | 結果 |
| --- | --- |
| 點左半邊或右半邊 | 該隊加一球：半場 +1、全場 +2，和網頁相同 |
| 左半邊或右半邊上滑 | 該隊 +1 |
| 左半邊或右半邊下滑 | 該隊 −1，分數不會減到負的 |
| 點上方的「半場／全場」按鈕 | 切換模式，所有裝置一起換 |
| 下鍵連按兩下 | 歸零：目前這場存進紀錄，開新的一場，隊名和模式沿用。3 秒內要按第二下，第一下只會提示 |
| 右滑或按上鍵 | 離開 App |

- **上鍵不能自訂**：它是電源鍵，系統會先攔走，App 收不到。
- **下鍵長按不能用**：系統會開 Samsung Wallet。
- **回饋**：操作生效時手錶震一下；沒生效（例如減到負分）震動不同。
- **畫面最下面一行小字**：「等平板連線／平板已連線」是藍牙狀態，「未上傳 3」是還沒送到雲端的操作數，「離線」是連不上雲端但沒有東西要送。這些都不影響記分。

## 比分存在哪

手錶上的比分是正本（2026-11-10 改的，之前每次操作都要連得到 Supabase 才算數）。

- **操作立刻生效**：加減分、切換模式、歸零都先改手錶上的比分並存檔，不等網路。App 被關掉重開比分還在。
- **排隊上傳**：每筆操作排隊送到 Supabase，沒網路就留著，連上後照順序補送。每筆加分帶自己的編號，重送不會重複計分。
- **什麼時候聽雲端的**：排隊的都送完了，手錶才採用雲端的比分（別的裝置改的分就是這樣進來的）。還有沒送出的時候以手錶為準。
- **上傳被拒絕**（不是連不上，是伺服器不收）：留在佇列不丟，「未上傳」的數字會一直不歸零。這時比分照記，但要找原因；清掉 App 資料可以重來。

## 藍牙直連平板

球場的熱點不可靠（2026-11-06 平板完全收不到手錶的比分），所以手錶另外用藍牙（BLE）把比分直接送給平板，不經過網路。

1. 手錶打開計分板。第一次會問藍牙權限，要允許。最下面出現「等平板連線」。
2. 平板用 Chrome 開計分板網頁，按底部的 ⌚，在清單選手錶。按鈕變綠、手錶顯示「平板已連線」就好了。
3. 之後平板的比分、隊名、模式都跟著手錶。在平板上點的加減分也是交給手錶記。

- **只有 Android 的 Chrome 能用**，iPad 不支援，⌚ 按鈕不會出現。
- **網頁要先載入**：藍牙只傳比分，網頁本身還是要有網路才打得開。到球場前先開好，不要重新整理。
- **斷線**：平板會自己重連，期間先顯示雲端的比分。一直連不回來就再按一次 ⌚ 重選手錶。
- **熄屏**：藍牙由前景服務維持，手錶回到錶面後連線應該還在（還沒實測）。服務閒置兩小時自己收工，再打開 App 會重新啟動。
- 平板上的撤銷、開新局、改隊名還是走網路，改完平板會通知手錶去雲端拿最新的。

格式和 UUID 寫在 `BleScoreService.kt` 開頭，網頁那一半在 `web/src/watch-ble.js`。

## 網路

上傳到 Supabase 要連得到外網。App 不用管走哪一條，系統會自動選：

| 手錶狀態 | 資料怎麼走 |
| --- | --- |
| 連著可用的 Wi-Fi | 直接走 Wi-Fi，不經過手機 |
| 沒有 Wi-Fi | 藍牙經手機上網，手機用 Wi-Fi 或行動數據都可以 |

所以在球場不用開熱點，手機能上網、藍牙連著就好。藍牙路線在手機連 Wi-Fi 時實測過；手機用行動數據又開熱點時（2026-11-06）平板沒收到比分，是哪一段斷的還沒查。

**斷網時**：照常記分，連上後補送，見上面「比分存在哪」。

手錶的 Wi-Fi 只有開發時才必要：電腦用無線 adb 連手錶除錯和安裝 App 要用它，打球時用不到。

## 開發

```bash
# PATH 上的 java 太舊時，先把 JAVA_HOME 指到 Android Studio 內附的 JBR
./gradlew assembleDebug

adb pair <手錶IP>:<配對埠> <配對碼>   # 只有第一次要配對
adb connect <手錶IP>:<連線埠>         # 連線埠常常換，看「無線偵錯」主畫面
adb install -r build/outputs/apk/debug/scoreboard-watch-debug.apk
```

依賴版本停在支援 compileSdk 36 的組合，因為 AGP 9.1.0 只支援到 36，要升級得連 AGP 一起升。

| 檔案 | 內容 |
| --- | --- |
| `src/main/java/.../MainActivity.kt` | 畫面、手勢、按鍵、每 2 秒同步一次 |
| `src/main/java/.../ScoreStore.kt` | 手錶上的比分正本、存檔、排隊上傳 |
| `src/main/java/.../BleScoreService.kt` | 藍牙把比分送給平板（前景服務） |
| `src/main/java/.../ScoreApi.kt` | 呼叫 Supabase REST API |

## 測試

目前沒有自動測試，都是在手錶上操作，而且會寫入正式資料。歸零會在比賽紀錄留下一場，不要的話到網頁刪除。

網頁那一半可以不用手錶測：用 playwright 塞一個假的 `navigator.bluetooth`，並攔下對 Supabase 的寫入（2026-11-10 這樣驗過顯示、通知、平板加分轉給手錶、斷線退回和重連）。手錶這一半到 2026-11-10 只編譯過，還沒上錶。
