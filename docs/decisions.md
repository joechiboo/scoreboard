# 設計決策與已知風險

## 決策

| 決策 | 原因 |
| --- | --- |
| **計分板用網頁，辨識端用 App** | 計分板要讓手機、平板、電視都能用，網頁打開即用；只有辨識需要鏡頭與裝置端推論，才做成 Android App |
| **Phase 1 不做房間代碼** | 初期使用者少，所有裝置看同一場比賽；資料表保留 `games`，之後加房間不用改加分事件 |
| **加分以事件記錄，比分由事件加總** | 多台裝置同時加分不會互相覆蓋；撤銷只標記 `undone`，資料不刪除，可追蹤 |
| **計分改為點一下／上滑 +1、下滑 −1** | 比 +1/+2/+3 按鈕更乾淨好按；操作說明收在「?」按鈕 |
| **全場點一下 +2、半場點一下 +1，上滑 +1、下滑 −1** | 全場一般進球 2 分、三分 3 分（點一下再上滑）；半場鬥牛每球 1 分、打到 6 分、沒有三分（2026-10-22） |
| **模式存在 `games.mode`，預設全場** | 所有裝置看到同一個模式；開新局沿用上一場，不用每場重選 |
| **畫面先樂觀更新** | 按了立刻變數字，伺服器確認後再校正，網路慢也不卡 |
| **App 只回報籃框，隊伍由資料庫決定** | 換場對調在網頁按一下，兩支手機不用各自改；避免 App 拿到舊的換場狀態而記錯隊 |
| **每筆自動進球帶 `client_id`** | 球場網路不穩時 App 可放心重送，資料庫自動忽略重複的那筆 |
| **自動進球固定記 2 分** | 罰球、三分由網頁改分；全自動三分需要另一個角度，列為後期 |
| **框選籃框，不讓 YOLO 偵測籃框** | 籃框不會動，框一次就好；模型只找球，更快更準，區外干擾直接排除 |
| **進球要過三道檢查** | 單鏡頭分不出遠近，加上球框大小比例與籃網晃動，降低麵包球誤判 |
| **錄影改拍廣角（含三分線）** | 一份素材可同時用於進球判定與之後的三分判定，避免重錄 |
| **Supabase publishable key 寫在程式裡** | 它本來就公開給前端使用，資料權限由 RLS 控管 |
| **比賽紀錄不另建資料表** | 每場的隊名、比分、時間 `games` 和 `game_scores` 已經有了；統計在網頁端算，不用改 schema |
| **不排賽程、不算輪替** | 輪替規則（四隊、13 分、連贏兩場兩隊一起下）由場上的人自己決定，系統只負責記錄與統計 |
| **進行中的那場不算進戰績** | 打到一半的比分（例如 1:1）會被當成平手；按「開新局」結束後才計入 |
| **刪除紀錄＝把該場加分全標撤銷** | 不真的刪資料，延續「事件只新增、撤銷只標記」；只還原這次標記的事件，原本就撤銷的不受影響 |
| **改比分＝補一筆手動加減分** | 原本的加分事件不動，看得出改過；每筆限 ±3，差太多拆成多筆 |
| **一天從凌晨 5 點起算** | 晚上打到過午夜的場次歸在同一天，分享時是同一份紀錄 |

## 已知風險

| 風險 | 影響 | 對策 |
| --- | --- | --- |
| **網址公開，任何人都能改分** | 比賽中被亂改 | 正式使用前加 PIN 碼（Phase 3） |
| **Supabase 免費方案閒置 7 天會暫停** | 比賽當天連不上 | 比賽前先打開網頁確認；必要時到 Dashboard 恢復 |
| **單鏡頭分不出遠近** | 麵包球被誤判為進球 | 腳架架高斜拍、大小比例與籃網檢查、網頁可撤銷 |
| **手機發熱、耗電** | 一整場撐不住 | 接行動電源；實測後再調整解析度或幀率 |
| **廣角時籃框和球很小** | 漏判 | 4K 錄影、只在偵測區推論；不夠準就改近拍專拍籃框 |
| **App 尚未在實機驗證** | 鏡頭畫面、框選、上傳可能有問題 | 安裝 APK 實測：模擬進球、斷網重送、框選 |
